# Архітектура

## Високорівнева схема

```
┌────────────────────────────────────────────────────────┐
│                     WINDOWS HOST                        │
│                                                          │
│  ┌──────────────────┐    ┌──────────────────────┐     │
│  │  winmux-desktop  │◄──►│  winmux-controller   │     │
│  │  (Tauri+xterm.js)│IPC │  (lifecycle, QMP)    │     │
│  └──────────────────┘    └──────────┬───────────┘     │
│                                      │ spawns          │
│                            ┌─────────▼────────┐        │
│                            │ qemu-system-x86_64│        │
│                            └─────────┬────────┘        │
└──────────────────────────────────────┼──────────────────┘
                                       │ virtio-{net,serial}
                          ┌────────────▼──────────────┐
                          │   Ubuntu 24.04 Minimal    │
                          │   ┌─────────────────────┐ │
                          │   │ winmux-init (PID 1) │ │
                          │   │ ↓ winmux-agent      │ │
                          │   │ ↓ sshd + bash + ... │ │
                          │   └─────────────────────┘ │
                          └───────────────────────────┘
```

## Шари

### 1. Frontend — `winmux-desktop` (Tauri 2)
- React 18 + TypeScript + xterm.js
- WebGL renderer для крейдяної графіки
- portable-pty (Rust) для PTY до ssh
- IPC через Tauri commands

### 2. Controller — `winmux-controller` (Rust)
- Spawn та lifecycle QEMU
- QMP клієнт (TCP, JSON-RPC) для динамічних команд
- TCP listener для подій від guest agent
- Port manager: на події з guest викликає `hostfwd_add`/`hostfwd_remove`
- Auto-create overlay якщо нема user.qcow2

### 3. Guest init — `winmux-init` (Rust, PID 1)
- Замінює systemd
- Mount /proc, /sys, /dev, /dev/pts, /run, /tmp
- Network: DHCP → static fallback (10.0.2.15)
- Persistent hostname & DNS (видаляє systemd-resolved симлінк, пише власний)
- Запуск sshd (з autogenerated host keys), winmux-agent, agetty з autologin

### 4. Guest agent — `winmux-agent` (Rust, musl static)
- Polls `/proc/net/tcp{,6}` кожні 500мс
- Знаходить нові LISTEN порти
- Шле події до controller через TCP (через NAT 10.0.2.2 → host 127.0.0.1:4445)
- Heartbeat кожні 10с

## Data flow: натиснута клавіша → результат

1. xterm.js ловить клавішу
2. → invoke("send_input")
3. → portable-pty master.write
4. → ssh.exe pipe
5. → SSH протокол через NAT
6. → sshd у guest
7. → bash
8. ← stdout читається ssh
9. ← portable-pty reader thread
10. ← emit("term-output")
11. ← xterm.js рендерить

Очікувана затримка: <5 мс на локальній машині.

## Auto port forwarding

```
guest python3 -m http.server 8080
       ↓
guest /proc/net/tcp [новий LISTEN на 8080]
       ↓ (~500мс)
winmux-agent виявляє
       ↓ JSON через TCP
winmux-controller отримує PortAdded event
       ↓ QMP human-monitor-command
"hostfwd_add tcp:127.0.0.1:8080-:8080"
       ↓
QEMU SLIRP створює правило
       ↓
Windows: curl http://127.0.0.1:8080  → працює
```
